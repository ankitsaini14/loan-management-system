Hosting architecture

Frontend — Vercel Next.js app in frontend/. Serves pages and proxies API calls.
Backend — Render Express API in backend/. JWT auth, business rules, file uploads.
Database — MongoDB Atlas Stores users, loans, and payments. Connected via MONGODB_URI on Render.
Authentication JWT stored in browser after login; sent on each /api request.

Request path (production)

User browser │ ▼ https://loan-management-system.vercel.app │ fetch("/api/auth/login", …) ← same origin ▼ Vercel rewrite (next.config.ts) │ ▼ https://lms-api-bz8e.onrender.com/api/… │ ▼ MongoDB Atlas

On Render’s free tier, the API may sleep when idle. The first request after sleep can take 30–60 seconds.

Loan status lifecycle

applied ──► sanctioned ──► disbursed ──► closed │ └──► rejected

Interest: 12% per year. Simple interest: SI = (P × R × T) / (365 × 100). Total repayment = P + SI.

Step-by-step workflows by role

1. Borrower

  1. Open the app → Log in or Sign up (borrower only).
  2. Complete personal details. Server runs BRE checks (age 23–50, salary ≥ ₹25,000, PAN, employment).
  3. Upload salary slip (PDF, JPG, or PNG; max 5 MB).
  4. Choose amount (₹50,000–₹5,00,000) and tenure (30–365 days) → submit application.
  5. Loan status becomes applied.

2. Sales executive

  1. Log in as sales@lms.dev.
  2. Open Dashboard → Leads: registered borrowers who have not submitted a loan yet.

3. Sanction team

  1. Log in as sanction@lms.dev.
  2. Open Sanction module: loans in applied status.
  3. Approve → sanctioned, or Reject with reason → rejected.

4. Disbursement team

  1. Log in as disbursement@lms.dev.
  2. Open Disbursement: sanctioned loans.
  3. Mark loan as disbursed.

5. Collection team

  1. Log in as collection@lms.dev.
  2. Open Collection: disbursed and closed loans.
  3. Record payment with unique UTR, amount, and date. Amount cannot exceed outstanding balance.
  4. When total paid equals total repayment → status closed.

6. Admin

  1. Log in as admin@lms.dev.
  2. Access every desk module (Sales, Sanction, Disbursement, Collection). Same rules enforced on the API.

Access rules (summary)

  • Borrowers cannot access the internal desk.
  • Each executive role sees only its module (except admin).
  • Protected routes require a valid JWT; expired or missing tokens redirect to login.
  • Logged-in users are redirected away from /login and /signup.
